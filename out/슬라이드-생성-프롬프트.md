SKT AI전략 조직 팀장 보고용 슬라이드 8장을 만들어줘.

## 배경
우리 팀은 매일 아침 'Daily Tech Brief'(AI/기술 뉴스 브리프)를 텔레그램 채널로
발송한다. 이 작업을 자동화한 파이프라인을 구축했고, 오늘(2026-08-03) 기준
동작 현황과 성과를 팀장에게 보고하는 덱이다.

**덱의 핵심 메시지 3줄**
1. 뉴스 수집부터 브리프 초안까지 자동화 파이프라인이 돌아가고 있다
2. 기계가 할 일과 LLM이 판단할 일을 나눠 설계했고, 사람이 실제 발송한
   브리프를 '정답지'로 삼아 매일 자기 채점하는 개선 루프를 붙였다
3. 아직 완전 자동화는 아니다. 후보 30건을 뽑아 사람이 최종 선별하는 단계이고,
   이를 20건 이내로 좁히는 것이 다음 목표다

## 청중과 톤
- 청중: 직속 팀장. 기술 배경 중간 수준. 큰 흐름은 도식으로, 핵심 근거는 수치로
- 톤: 담백한 사실 중심. 과장 금지. **파이프라인 설명이 이 덱의 중심**이고
  성과는 그 뒤를 받치는 역할
- 팀장이 가장 궁금해할 지표는 **매칭률**(사람이 실제 고른 기사를 얼마나 맞혔나)

## 반드시 지킬 것
- **아래 제공한 수치 외에 숫자를 지어내지 마.** 없는 값은 비워둬
- 슬라이드당 메시지 하나. 헤드라인은 완결형 문장으로
- 이모지 쓰지 말 것

## 슬라이드 구성

### 1. 표지
제목: Daily Tech Brief 자동화 파이프라인
부제: 구조 · 운영 현황 · 개선 루프 | 2026-08-03 기준

### 2. 전체 그림 (한 장 요약)
가로 흐름 도식 하나로 전체를 보여줄 것:

`수집` → `정제·채점` → `후보 생성` → `LLM 선별·작성` → `텔레그램 발송` → `정답지 대조` ↺(수집으로 회귀)

각 단계 아래 오늘 기준 숫자를 작게:
- 수집 5,700여 건 → 정제 후 후보 388건 → 브리프 초안 30건 → 사람 최종 발송 17건
- 맨 아래에 "정답지 대조 → 결함 수정 → 재검증" 화살표가 되돌아가는 루프 강조

### 3. 어디서 가져오는가 — 3계층 수집
세로 3단 카드로:

**Tier 0 — 큐레이션 (오늘 75건)**
사람·봇이 이미 한 번 거른 입력. 가장 신뢰도 높음
- 사내 트렌드 채널 뉴스봇 12건
- 에이닷 비즈 뉴스레터 50건 (5개 토픽 × 10건)
- 삼성 글로벌 AI/SW 뉴스 9건 (요약만 오고 링크 없음)
- 자체 트렌드 브리핑 4건

**Tier 1 — 매체 RSS**
Axios·CNBC·이데일리·Google AI 블로그·Meta 뉴스룸 등 47개 피드 상시 수집

**Tier 2 — 구글뉴스 검색 (오늘 고유 5,670건)**
92개 키워드 쿼리로 폭넓게 훑는 그물. 놓침을 줄이는 안전망 역할

→ 카드 옆에 "위로 갈수록 신뢰도, 아래로 갈수록 커버리지" 축을 표시

### 4. 기계와 LLM의 역할 분담 (이 덱에서 가장 중요한 슬라이드)
좌우 2열로 대비시켜 시각화:

**기계가 하는 일 — 규칙이 명확하고 양이 많은 것**
- 수집·중복 병합·클러스터링 (5,700건 → 2,955개 사건 묶음)
- 규칙 기반 점수화 (키워드·보도 매체 수·교차 출처·금액 규모·발행일)
- 카테고리 자동 분류, 원문 링크 해결, 발행일 창 필터

**LLM이 하는 일 — 판단이 필요한 것**
- 삼성 채널처럼 링크 없이 요약만 오는 입력의 원문 찾기
  (검색어 생성 → 후보 중 '같은 사건' 판별. 기계 역추적은 정확도 40~63%에 그침)
- 링크를 못 찾은 후보를 웹검색으로 복구
- 최종 30건 선별 + 주요 내용·시사점 작성 + 관련 조직 태깅
- 정답지 대조 시 '같은 사건인가' 판정 (URL이 달라도 같은 사건인 경우가 많음)

→ 하단 한 줄: "링크를 LLM이 만들지 않는다. 검색 결과 중에서 고르기만 한다 (환각 차단)"

### 5. 처리 흐름 — 5,700건이 30건이 되기까지
깔때기(퍼널) 도식:
- 수집 5,700여 건
- 사건 단위 병합 → 2,955개 클러스터
- 점수 임계 통과 + 큐레이션 고정 → 후보 318건
- 링크 미확보 구제 후보 150건 추가 → LLM에게 총 388건 제시
- LLM 선별 → 브리프 초안 30건
- 사람 최종 검토 → 발송 17건

→ 옆에 주석: "큐레이션 출처는 점수와 무관하게 후보에 고정 포함.
   기계 점수로 사람이 고른 기사를 떨어뜨리지 않기 위함"

### 6. 개선 루프 — 매일 자기 채점
순환 다이어그램 (4단계):
`브리프 발송` → `사람이 실제 발송한 최종본을 정답지로 확보(GitHub 아카이브)`
→ `자동 대조 채점` → `결함 수정 후 재검증` → 다시 처음으로

- URL 일치는 하한값일 뿐 — 같은 사건을 다른 매체로 실으면 URL이 다르므로
  LLM이 사건 단위로 다시 센다
- 오늘 이 루프로 결함 6가지를 찾아 수정

### 7. 오늘 기준 성과
상단에 매칭률 3개를 큰 숫자로:

| 지표 | 값 | 의미 |
|---|---|---|
| 후보 노출률 | **16/17 (94%)** | 사람이 고른 기사를 파이프라인이 후보에 올렸는가 |
| 사건 기준 일치 | **12/17 (71%)** | LLM이 30건으로 좁혔을 때 사람과 겹친 정도 |
| 정밀도 | 12/30 (40%) | 뽑은 30건 중 실제 채택된 비율 |

하단에 오늘 개선 전/후 비교를 작게:
| | 개선 전 | 개선 후 |
|---|---|---|
| 후보 노출률 | 11/17 | 16/17 |
| 큐레이션 채널 링크 확보 | 8% | 83% |
| 뉴스 수집량 | 2,758건 | 5,670건 |

→ 해석 한 줄: "수집·후보 단계는 94%로 거의 놓치지 않는다.
   남은 과제는 388건에서 30건으로 좁히는 선별 정확도"

### 8. 다음 단계 — 완전 자동화로
- **현재**: 후보 30건 제시 → 사람이 최종 15~17건 선별 (사람 개입 필요)
- **목표**: 후보를 20건 이내로 좁히면서 사건 기준 일치율을 끌어올려
  사람 검토를 '확인'으로 축소 → 완전 자동화
- **방법**: 매일 정답지 대조로 편향을 계측해 선별 기준에 반영
  (예: 국내 연구성과·국책과제·보안통계를 기계가 저평가하는 경향을 실측해 보정)
- 병행 과제: 제약·바이오 등 전문지 커버리지 보강

## 디자인 가이드
- SKT 사내 보고 톤. 차분한 다크 네이비 배경 + 화이트 텍스트, 강조색은 오렌지 하나만
- 한글 고딕 계열. 숫자는 크고 굵게

- 4번(기계 vs LLM)과 5번(퍼널)이 이 덱의 하이라이트
