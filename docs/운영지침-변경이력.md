>
> **결론: 가능하다. 단 삼성 소스(09-15 전환)와 경로가 다르다.** 기존
> `slack-save` 경로로는 **0건**이 나온다. 이유와 고친 것을 적는다.
>
> ### 무엇이 다른가 — 본문이 메시지가 아니라 파일로 온다
> 삼성 뉴스는 사람이 슬랙에 **붙여 쓴 메시지**라 `slack_read_channel` 이
> 텍스트를 그대로 준다. 뉴스클립은 채널 이메일 주소로 **메일이 게시**되는데,

> ```
> === Message from Slackbot (USLACKBOT) at 2026-09-17 10:46:57 KST ===
> Files: [2026년 9월 17일] 조간 뉴스 클리핑 (ID: F0C2AHG0X3P, text/html, 40.0 KB)
> ```
> **메시지 텍스트는 빈 문자열이다.** 그래서 `run.sh slack-save` → `log` →
> `tier0` 경로에 넣으면 조용히 0건이 된다.
>
> `slack_read_file <file_id>` 로 읽으면 JSON 이 나오고, 그 안의 **`body-plain`**
> 이 지메일 본문과 **같은 형식**(`N. 제목 (매체)` + `o 링크: URL`)이다.
>
> ### 고친 것 셋
> **① `cowork/slack_email_body.py` 신설 (`run.sh newsclips-slack`).**
> `slack_read_file` 응답을 통째로 받아 `body-plain` 만 꺼내 **기존 지메일
> 파서로 넘긴다.** 파서를 새로 만들지 않았다(09-15 교훈: 파서가 둘이 되면
> 또 어긋난다). `body-plain` 이 없으면 `body-html` 을 평문화하는 폴백이 있다.
> **`body-plain-without-links` 를 잘못 집으면 링크가 전부 비므로** 그 경우를
> 감지해 경고한다.
>
> **② 파서가 줄바꿈된 URL 을 못 받고 있었다 — 26건 중 3건 탈락.**
> 메일 클라이언트가 긴 URL 을 다음 줄로 넘긴다:

> 때문). 실측: 6·11·26번. `(\S*)` 로 바꾸고 다음 URL 줄을 기다리게 했다.
> 회귀검사 — 지메일 원본 26/26, 삼성 슬랙 19/19 그대로.
>
> **③ `--dry` 가 부작용을 남기고 있었다.** dry 로 시험하는 중에 그날 실제
> 원문 감사 파일(`cowork/raw/newsclips-mail-<날짜>.txt`)을 테스트 본문으로

### 4. 09-10 내 판단 실책 — 애플 워치 '고' / 아이폰 듀오 '중'

사용자가 세 번 물었다. **"A·B 가 동점이고 듀오는 보도도 다수인데 왜 중이냐."**
판정 당시 내가 실제로 적은 근거는 아래 둘이었다. 둘 다 판정 축이 아니다.

> (tier0+교차 48행) "여러 애플 기사가 중복. 같은 사건(애플 신제품 발표).
>  하나만. 선택: 247(AI 건강 코치, 15초 대화 복기) — **알맹이 있음.** 고"
> (tier1 153행) "**하지만 첫 폴더블폰은 별개 제품/사건으로 볼 여지.** …
>  **애플 이벤트 2건은 과함.** … **AI 관련성이 더 높은 건 247.** 202는 중"

**틀린 곳 셋.**
1. **판정 기준을 바꿔치기했다.** 이 브리프의 기준은 'AI 산업에 파급이 큰
   사건인가'인데, 나는 **제목의 AI 어휘 밀도**('AI 건강 코치·시리 리캡'이
   보이니까)로 골랐다. 애플의 첫 폴더블 진입은 폼팩터 경쟁 구도를 바꾸고
   삼성에 직접 걸리는 사건이다. A×B×C 를 따졌으면 듀오가 위다
   (C축: 워치 시리즈12 = **기존 라인 연례 갱신** / 듀오 = **새 제품군 최초**).
2. **'2건은 과함'이라는 분량 걱정을 등급에 반영했다.** 지침은
   "'고' 가 더 많아도 등급은 그대로 두고 rank 로 자른다. 판정을 조작하지 말 것".
   둘 다 '고'로 두고 rank 에서 갈렸어야 했다.
3. **'별개 사건으로 볼 여지'라고 스스로 적어놓고 무시했다.** 앞 그룹에서
   이미 결정했다는 이유로 덮었다. 이게 가장 나쁘다.

**기계는 애초에 별건으로 나눠놨다.** refined 클러스터
`307 size=2 애플워치` / `255 size=10 아이폰 듀오` / `134 size=43 아이폰18 프로`.
**둘을 '같은 애플 이벤트'로 합친 것은 나 혼자였고, 합치면서 size 2 를
대표로 삼고 size 10 을 버렸다.** blind 목록에 보도 폭이 '소수'(워치) /
'다수'(듀오)로 이미 찍혀 있었는데 보지 않았다.

**확정 규칙 3가지**
- **(A) 기계가 나눈 클러스터를 임의로 합치지 않는다.** 같은 회사·같은 행사라도
  refined 클러스터가 다르면 별건으로 판정한다. 합치려면 사유에 근거를 적는다.
  '같은 사업·공고·설명회 1건' 규칙은 **정부 사업 대상**이지 제품 발표가 아니다.
- **(B) 부득이 합칠 때 대표는 클러스터 size·보도 폭이 큰 쪽.**
- **(C) 제품 출시의 C축**: 기존 라인 연례 갱신(워치 시리즈N, 아이폰 N 프로)은
  '중', 새 제품군 최초 출시(첫 폴더블, 첫 카테고리)는 '고'. 지침 C축의
  '기존 모델 부분 개선은 한 단계 낮다'를 **하드웨어에도 적용한다**
  (종전에는 AI 모델에만 적용했다).

정정 효과(오늘 재계산): 202 를 '고'로 두면 rank 14 로 발송본에 들어오고,
ntag 제거와 겹쳐 top16 적중 **3/8 -> 5/9**.

## 2026-09-09 변경 2 — tier0 봇큐레이션 소스 `aibrief` 추가 (사용자 지시)

> "앞으로 tier0 뉴스 소스에 우리 루틴에 있는 일일 AI 뉴스 브리핑도
>  봇큐레이션 소스로 추가해줘."
> "매일 8시에 AI 뉴스 큐레이션 실행하는 게 있어. 그 결과를 가져오면 돼."

### 왜 파일 전달인가 — 직접 못 읽는다
그 08:00 작업은 **다른 Claude 스페이스**에서 돈다. 이 스페이스에서
`list_scheduled_tasks` 를 부르면 3개(morning-brief·국책과제 체크·DTB 자동화)만
나오고, `list_sessions` 131건에도 해당 작업 세션이 없다. **DTB 실행 중에
그 결과를 직접 읽을 방법이 없다.**

그래서 **연결 폴더의 `inbox/aibrief-<날짜>.md`** 를 약속된 전달 지점으로 둔다.
파일이 없으면 조용히 건너뛴다(에러 아님). 슬랙·지메일로 경로가 바뀌면
그때 파서를 그쪽에 붙이면 된다.

### 고친 것
- **`cowork/aibrief_ingest.py` 신설** — 브리핑 텍스트에서 (제목, URL, 매체)를 뽑아
  `out/tier0-<날짜>.json` 에 `src: "aibrief"` 로 덧붙인다.
  **서식 4종을 모두 받는다**(어느 형태로 올지 모르므로):
    1. `- [제목](URL)`                        마크다운 링크 목록
    2. `▪ **제목** (매체, [원문보기](URL))`    DTB 발송본 서식
    3. `1. 제목 (매체)` + `o 링크: URL`        NewsClips 메일 서식
    4. `제목 — URL`                            같은 줄
  섹션 헤더(`## …`, `**■ …**`)·빈 줄·요약 문단은 무시하고,
  **URL 이 없는 항목은 버린다**(링크 해결 쿼터만 먹는다).
  지메일 `google.com/url?q=` 래핑도 벗긴다.
- `cowork/run.sh aibrief` — `inbox` 파일 우선, 없으면 stdin 히어독. `dry` 지원.
- `cowork/tiers.py` `KNOWN_TIER0` 에 `aibrief` 추가.
- `refine.py`
  - `CURATED_AI` 에 `aibrief` 추가 → **봇큐레이션(+1)**. 사람큐레이션(+5) 아님.
    사람이 아니라 에이전트가 웹서치로 고른 목록이기 때문이다.
  - tier0 고정 핀 `CURATED` 집합에도 추가 → 점수와 무관하게 후보에 살아남는다.
  - `FILTER_EXEMPT` 에 자동 포함 → 잡음 필터 면제, 전량 판정 대상.
- blind 목록에는 **`tier0-봇큐레이션`** 그룹으로 뜬다(`blind_list.py` 가
  signals 의 'AI큐레이션' 표시로 가르므로 별도 수정 불필요).

### 파서에서 잡은 버그 2건 (실측)
1. `RE_MD_LINK` 의 라벨 길이 하한이 6이라 **'원문보기'(4자)를 못 잡았다.**
   그래서 DTB 서식 줄이 통째로 bare-URL 분기로 새고 제목이
   `엔비디아, 리벨리온에 M&A 제안 (한국경제, [원문보기](` 로 잘렸다.
   하한을 1로 내리고 짧은 라벨은 `NOISE_TITLE` 이 거르게 했다.
2. `원문보기: URL` 처럼 **라벨만 있는 줄**이 위 줄에서 제목을 끌어와
   같은 기사를 두 번 넣었다. 라벨 줄은 그냥 버리도록 고쳤다.

### 실행 순서
4단계 tier0 수집에서 **`run.sh tier0` 뒤, `linkcheck tier0` 앞**에 넣는다.
```
run.sh tier0  →  newsclips-mail  →  samsung-mail  →  **aibrief**  →  linkcheck tier0

### 4. 시사점에 인사이트를 담을 것 — **초판을 같은 날 정정했다**
> "시사점에 가끔 의미 없는 게 있는 것 같다. 좀 더 인사이트가 담겨 있으면 좋겠다."

**둘 다 틀렸다.**

> **사용자 정정 원문**: "시사점 지침은 원래대로 명사형으로 종결해줘.
> 시사점을 단순히 글자수를 늘리는 게 중요한 게 아니고 경영층에게 의미 있는
> 인사이트를 주는 데 노력하라는 의미였어."

**[확정 규칙]**
- **길이는 종전대로 40자 안팎(최대 55자).** 45자로 늘렸던 것을 되돌린다.
  **짧아도 판단이 있으면 좋은 시사점이다.** 40자를 채우려 군더더기를 붙이지 말 것.
- **명사형 종결은 이 브리프의 확립된 문체다.** `~가속화` `~부상` `~확산`
  `~재조명` 을 **그대로 쓴다.** 어미를 금지하지 않는다.
  주격조사(이/가)를 마지막 명사 앞에 붙이지 않는 규칙만 유지한다.
- **판정 기준은 어미가 아니라 '새 정보의 유무'다.**
  자문할 것은 하나 — **헤드라인과 주요 내용을 읽은 경영층이, 시사점을 읽고
  새로 얻는 것이 있는가.**
- `brief.py` 작성 기준:
  1. **문체는 명사형 종결 유지.** 어미가 문제가 아니라 판단이 없는 것이 문제다.
  2. **사실의 재진술 금지.** 주요 내용을 명사형으로 바꾼 것은 시사점이 아니다.
     이것이 '의미 없는 시사점'의 실체다.
  3. **넷 중 하나를 답할 것** — a.무엇이 바뀌나 b.무엇을 시사하나
     c.우리에게 무엇인가 d.무엇을 지켜봐야 하나. 답이 없으면 그 기사를 뺀다.
  4. 두 절을 쉼표로 잇지 말고 판단 한 줄만.
  5. 과장·추측 금지.
- **`cowork/insight_check.py`** (`run.sh insight`) — **어미 목록 검사를 폐기**하고
  아래 셋으로 바꿨다. **경고 전용, 종료코드 0.**
    - **동어반복** — 시사점 실질 어절의 50% 이상이 주요 내용·헤드라인에 이미 있음
    - **새 정보 없음** — 기사에 없는 실질 어절이 2개 미만
    - **극단적으로 짧음** — 15자 미만 (40자를 채우라는 뜻이 **아니다**)
  `STOP` 목록에 `가속 가속화 본격화 확산 부상 …` 을 넣어 **종결어를 제외하고**
  실질 어절만 비교한다. 그래야 '새 정보'가 제대로 세어진다.
- **실측 효과**: 09-08 발송본 25건 기준 초판은 **24건 오탐**(대부분 '너무 짧음',

   -> 뉴스1: `/ai-now` 18건 + `/it-science`(alt) 11건.
2. **`parse_urldate`** — 목록 HTML 의 앵커를 `article_re` 로 거르고
   **발행일을 URL 에서 뽑는다.** 디지털데일리 기사 URL 이
   `/page/view/2026090814591613726` 처럼 앞 8자리가 발행일이다(한국 언론 CMS
   에 흔한 형식). -> 60건.

### 곁다리로 고친 것 — `parse_date` 의 날짜만 있는 값
`datetime.fromisoformat('2026-09-08')` 은 **로컬(KST) 자정**으로 읽히고
`.astimezone(utc)` 를 거치면 `2026-09-07T15:00Z` 가 되어 **달력 날짜가 하루
당겨진다.** refine 의 발간일 창은 `published[:10]` 을 KST 날짜와 비교하므로
디지털데일리 오늘 기사가 전부 '어제'로 잡혔다(창이 2일이라 유실은 없었지만
꼬리가 하루 잘린다). `YYYY-MM-DD` 단독 값은 UTC 자정으로 고정하도록
`parse_date` 맨 앞에 분기를 넣었다. 시각이 붙은 값의 동작은 그대로다.
