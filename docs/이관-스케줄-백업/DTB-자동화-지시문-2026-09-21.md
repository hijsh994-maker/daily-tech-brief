```
=== Message from Slackbot (USLACKBOT) at YYYY-MM-DD HH:MM KST ===
Files: [YYYY년 M월 D일] 조간 뉴스 클리핑 (ID: F..., text/html, NN KB)
```
    **메시지 텍스트가 비어 있는 것이 정상이다.** '메일이 안 왔다'고 오판하지 말 것.
    같은 채널에 `FW: News Clips(M월 D일)` 같은 11MB 첨부가 함께 올라올 수 있는데
    그건 다른 파일이다. **「조간 뉴스 클리핑」 제목의 것을 집는다.**
(2) `slack_read_file(<그 file ID>)` 로 파일을 읽는다.
    응답이 커서 도구가 파일로 떨어뜨리면 그 파일을 그대로 표준입력으로 넣는다
    (내용을 다시 타이핑하지 말 것).
(3) 응답을 **그대로** 히어독으로 넘긴다(헤더·`<file_content>` 래퍼 포함, 가공 금지):

```
bash cowork/run.sh newsclips-slack <<'RAW'
<slack_read_file 응답 전체>
RAW
```

- **주제 필터는 두지 않는다. 파싱된 것을 전량 주입한다.**
  조간 지면 **전체**라 AI 무관 기사가 섞여 있다. 7단계 판정에서 거른다.
- 출력의 **`링크 보유 N/M`** 이 90% 미만이면 경고가 뜬다. 보고에 적는다.
- **`[경고] '링크:' 뒤가 모두 비었습니다`** 가 뜨면 `body-plain-without-links`
  를 집은 것이다. 파일을 다시 읽어 넘긴다.
- 채널에 아직 안 올라왔으면 조용히 건너뛰되 **보고에 반드시 한 줄 적는다.**
- 미리보기만: `newsclips-slack dry` (원문 저장 안 함)
- 지메일이 살아 있는 계정에서 과거 날짜를 되짚을 때만 `newsclips-mail` 을 쓴다.

**tier0 소스는 4개다: slack(#3_트렌드) / adot / samsung(슬랙) / newsclips(슬랙).**

## 5단계 - 삼성 큐레이션 (슬랙)
```
bash cowork/run.sh samsung-slack
```
- **tier0 를 먼저 돌린 뒤에** 부른다.
- 슬랙 삼성 섹션은 `번호. 제목 (매체)` + `o 링크:` 형식이라 **링크가 100% 붙는다.**
- 매체가 `디지털데일리 / Daum뉴스` 처럼 오면 **슬래시 앞(원 매체)만** 취한다.
- 채널에 안 올라온 날에만 구 매칭 경로를 쓰고, 보고에 '삼성 슬랙 미게시' 라고 적는다.
  (실측 09-18: 미게시라 `[실패] 0건 파싱` 이 떴다. **이건 파서 고장이 아니다.**)

### 5-1단계 - tier0 링크 검사 (생략 금지)
```
bash cowork/run.sh linkcheck tier0        # timeout_ms 175000
```
- URL 모양(목록/홈 페이지) + HTTP 404/410 + 제목 대조 세 가지를 본다.
  403 은 봇 차단이라 정상 취급한다.
- **'실패' 판정 URL 은 자동으로 비운다.** 뒤의 `run.sh links` 가 다시 찾는다.
- **'의심'은 자동으로 손대지 않는다.** 페이지 제목이 함께 찍히니 눈으로 보고,
  명백히 다른 기사면 7단계에서 그 항목을 빼거나 다른 후보로 바꾼다.
  (지면 제목과 온라인 제목이 달라서 뜨는 '의심'이 대부분이다. 같은 기사면 둔다.)
- 반드시 **refine 앞에** 돌린다.
- **'미확인' 숫자만 보지 말고 `검사 커버리지` 줄을 볼 것.**
  종료코드: **0 정상 / 1 고쳐야 할 링크 있음 / 2 검사 커버리지 미달**
  2 가 나오면 run.sh 가 자동으로 1회 재시도한다. 그래도 2 면 보고에 적는다.
- 보고에 `OK/의심/실패/미확인` 과 **`검사 커버리지 N/M`** 을 적는다.

## 6단계 - 파이프라인
`bash cowork/run.sh tier2` → `refine` → `links`(반복) → **`body`(반복)** → `brief` → `extend`

**tier2 / links / body 는 전부 timeout_ms 175000 으로 부른다. 인자를 붙이지 말 것.**

- tier2 는 재개형이다. '남음 N개' 가 없어질 때까지 반복한 뒤
  `bash cowork/run.sh tier2-done` 으로 마감해야 out/tier2-<날짜>.json 이 생긴다.
- refine 이 죽으면 링크 해결이 원인이다. 이렇게 나눈다:
    `cd $W && python3 refine.py --date <날짜> --min-score 6 --max-items 300 \
       --max-rescue 150 --no-links`   (1~2초)
    그다음 **`bash cowork/run.sh links`** 를 '남았습니다'가 안 나올 때까지 반복.

**links 는 실패 사유를 갈라 찍는다.**
  `확보 N / 못찾음 N / 네트워크성 N / 건너뜀 N / 남음 N(재시도 대기 N)`
  - **못찾음** = 네이버에 그 기사가 정말 없다. 재시도하지 않는다.
  - **네트워크성** = 회복 가능하므로 미시도분을 다 소진한 뒤 한 번 더 시도한다.
  '전부 시도 완료' 가 나올 때까지 반복한다.
  - **워커를 8보다 올리지 말 것.** 병목은 네이버 쿼터이고 처리량은 초당 0.4건 고정이다.

**`bash cowork/run.sh body` — 본문 재채점. 생략 금지.**
- links 를 다 채운 뒤, brief **앞에** 돌린다. 순서가 바뀌면 소용없다.
- 재개형이다. '남았습니다'가 안 나올 때까지 반복(**2~4회**).
- **아래 두 줄을 확인하고 보고에 적는다.**
    `받기 실패 N건 -> 타임아웃 N / HTTP 403 N / 본문짧음 N`
    `본문 보유율 N/M (P%)`  ← **60% 미만이면 경고가 뜬다. 뜨면 반드시 보고한다.**

**brief 뒤 extend 가 실제로 붙었는지 즉시 확인한다.**
`grep -c "^\[링크 미확보 후보\]" out/prompt-<날짜>.txt` 가 **1** 이어야 한다.
0 이면 미확보 150건이 통째로 빠진 것이고, 그 프롬프트로 한 선별은 무효다.
(`extend` 가 '이미 덧붙여져 있음. 건너뜀' 을 찍어도 grep 이 1 이면 정상이다.)

## 7단계 - 전수 판정 → 순위 → 발송본 작성

### (1) 점수를 가린 목록 + 타임라인 만들기
```
bash cowork/run.sh blind
bash cowork/run.sh timeline
```
`out/candidates-blind-<날짜>.txt` 는 score·signals 를 빼고 통로별로 묶은 목록이다.
**점수 내림차순이 아니므로 위에서부터 읽어도 '상위/하위'가 없다.**
표시 셋을 함께 읽는다 — `⟨체급⟩`(주체가 이 바닥에서 누구인가) ·
`[중복의심]` · **`[기자재어휘]`**(D축 배제7 후보). 셋 다 점수가 아니라 **사실**이다.

`out/timeline-<날짜>.md` 는 최근 30일을 사건 단위로 늘어놓고 오늘 후보를 붙인다.
줄 앞의 `·` 는 **후보로만 올랐고 발송되지 않은** 기사다. 여러 날 이어져 있으면
철 지난 주제이므로 새 사실이 없으면 올리지 않는다.

### (2) 전수 판정
**`out/prompt-<날짜>.txt` 의 `[편집자 평가 기준]` 절을 반드시 연다.**
D축(어젠다 경계)·E축(알맹이)은 **거기에만 있다.** 타임라인·사례집·사업현황은
신규성과 자사 관련성만 담당한다. (실측 09-17: 프롬프트를 안 열어 D축 배제7
'발전기'와 09-14 지시 'GPU 물량 확보는 중'을 둘 다 어겼다.)
그리고 **`docs/사례집.md`** 를 읽는다(규칙표보다 이것이 먼저다).
**판정은 blind 목록으로만** 한다.

- **후보 목록의 score/signals 를 판정 근거로 쓰지 말 것.** 사용자 지시다.
- blind 목록의 **전 건**에 고/중/저를 매겨 `out/verdict-<날짜>.csv` 로 저장한다.
  **형식: `idx,grade,reason,rank` (헤더 포함, grade = 고|중|저)**
  rank 는 이 단계에서 비워 두고 (3)에서 채운다.
  '저'는 닫힌 코드를 쓴다: `배제7-<항목명>` / `운영공지` / `채용인력` /
  `사설칼럼` / `시황실적` / `중복` / `AI무관` / `평이`
  **'중' 의 사유도 한 종류로 뭉개지 말 것.** 축 이름을 남긴다
  (E축 알맹이 / C축 진행 / F2 중국 / F6 학계 / F7 언론사 / 지표갱신 / 중복 …).
  `verdict` 가 '중' 사유가 1종뿐이면 경고한다.
- **'고' 의 사유에는 반드시 넷이 들어간다.**
  1) `올린 근거 / 내릴 뻔한 근거와 넘는 이유` — **'/' 가 없으면 종료코드 1**
  2) `새사실:<한 문장>` — 어제 기사와 무엇이 다른가. **본문에 실제로 있는 말**로
     쓴다. `newfact` 가 bodycache 와 대조해 지어낸 문장을 잡아낸다
  3) `[중복의심]` 이 붙었으면 `중복검토:<한 줄>`
  4) 해당하면 `기자재검토:` / `물량검토:` / `동일주체:` (아래 agenda 게이트)
  **축 이름을 남긴다**(F1·지정학·E-c·F10·독파모 등). (3)에서 순위 가중치로 쓴다.
  사업현황에 걸리면 `사업현황:<줄 이름>` 도 적는다.
- **50~80건씩 끊어서** 판정한다. 통로 그룹 경계(=== )에서 끊으면 자연스럽다.
- 판정이 끝나면 검사한다:
```
bash cowork/run.sh verdict
```
  `verdict` 는 반증·새사실 본문대조(`newfact`)·사례집 무결성(`case`)·
  **어젠다 게이트(`agenda`)** 를 한꺼번에 돌린다. **종료코드 0 으로 만든다.**

**어젠다 게이트 — 09-17 신설. 해명 없이는 발송이 막힌다**
  - **기자재**: 발전기·변압기·전선·버스덕트·냉각·공조·철강 등이 걸리면
    `기자재검토:` 를 요구한다. **D축 배제(7) AI DC 기자재 납품은 금액이 커도
    '저'이고 F1 보다 우선한다.** 구분선은 *무엇이 들어가나*(전력계약·부지·
    자금조달 = 핵심) vs **누가 물건을 파나**(납품 = 어젠다 밖).
    **AI 반도체용 소재 증설(CCL·유리기판 등)도 이 축에 가깝다.** 파는 쪽이면
    금액이 조 단위여도 '중' 으로 두고 `deals` 보고에 사유를 적는다(실측 09-18).
  - **물량**: `새사실:` 이 GPU·칩 **물량 수치뿐**이면 `물량검토:` 를 요구한다.
    09-14 지시 — *"단순 GPU·컴퓨팅 구매(구매 공시·물량 확보)는 금액이 커도 '중'.
    F1 이 뒤집지 못한다."*
  - **동일주체**: 같은 주체 + 같은 사업 낱말이 '고' 에 2건 이상이면 `동일주체:`.
    같은 날 같은 회사·같은 사업은 **하나만** 싣는다.

**판정 축(프롬프트 [편집자 평가 기준] 요약)**
  A 주체 × B 주제 × C 단계 × D 어젠다 로 1차 분류하고,
  **E 알맹이 · F 하드규칙 · G 신규성 · H 편집자 평가** 로 보정한다.
  - **F1 금액 1천억원 이상이면 '큰 건'.** 단 **D축 기자재 배제가 F1 보다 우선**이고,
    **단순 물량 확보는 F1 이 뒤집지 못한다.**
  - **F9 SKT 가 주어면 한 칸 하향**(고→중, 중→저). '제외'가 아니다.
    경쟁사와 나란히 나오면 '고'.
  - **F10 경쟁사 + 핵심 어젠다는 '고'.** 경쟁사라고 내리지 말 것.
    경쟁사는 **KT·네이버·카카오·LGU+·LG 다섯 곳 모두 1급**이다. 서열을 매기지 말 것.
    볼 것 넷 — 신규 서비스·솔루션 출시 / AI 사업 전략 / 사업 수주 / 파트너·인력·조직.
  - **D축은 닫힌 배제 목록이다.** 배제 **10항목**(반도체 소자연구·양자·보험·
    증권상품 출시·통신망·이미지센서·**DC 기자재**·**특파모 사업**·**특허/지식재산 제도**·
    **건설사 주체 AIDC 시공**) 중
    **이름을 댈 수 있을 때만** '저'로 내린다. 못 대면 D축 적용 금지.
  - **F10 의 '논의·검토' 단계 단독 보도는 예외가 아니다**(09-21 LG CNS 데이브레이크).
  - **중국 빅테크의 신규 모델·오픈소스 공개는 F2 하향으로 '중'에 두지 말 것.**
  - **컨소시엄 '참여사 합류'는 최초 발표 때 이미 공개된 사실**이라 후속 기사에
    새 사실이 없는 경우가 많다(09-18·09-21 신한은행 건).
  - **해외 규제·수출통제·반도체 규제는 한 단계 내린다**(사업현황 8절 Q10 "없음").
    09-03 의 '미국 정부·의회 AI 정책을 깎지 말 것'은 **09-14 에 폐기됐다.**
    **국내 AI 서비스 규제 입법은 '추진' 단계여도 고.**
  - **8-1 지정 인물 조건부 가점 — 최태원·유경상.** 내용이 AI 관련일 때만.
  - **휴머노이드 상용화 · 로봇 파운데이션/월드모델/학습데이터 플랫폼은 한 단계 올린다.**
    나머지 산업용 자동화 로봇은 '중' 이하(실측 0/12).
    휴머노이드 탑티어(어질리티·보스턴다이내믹스·유니트리·피규어)는 **신제품
    공개·자본 이벤트만으로도 rank 상단**이다.
  - **빅테크의 요금제·구독 출시는 운영 공지가 아니라 제품 출시다**(rank 상단).
  - **SK 그룹사 AX 기사는 사내 사례가 아니라 캡티브 영업 정보다.**

**어젠다 키워드는 등급이 아니다.** 모두의AI·독파모·소버린·국책과제·로봇·AIDC 가
제목에 있다는 것은 **검토 대상으로 끌어올리는 신호일 뿐**이다. 그다음 두 질문을
반드시 통과시킨다 — **이 기사에서 새로운 것이 무엇인가** / **이 주체가 그 사건의
중심인가(그리고 AI 업계 플레이어인가)**.

**tier0 는 전량 판정한다.** 뺄 때는 사유를 댈 수 있어야 하고,
**'점수가 낮다'는 사유가 아니다**(애초에 점수가 안 보인다).

**사람큐레이션(삼성·NewsClips)은 전량 '검토'지 전량 '채택'이 아니다.**
  판정은 다른 후보와 똑같이 적용하고 '저'면 뺀다.

**지면(NewsClips)은 조간 전체가 들어온다 — 여기서 거른다.**
  - 핵심 어젠다 밖이면 '저'. 스포츠·연예·사건사고, 단말/가전 판매,
    자사주·배당·주가 시황, 통신 요금제·네트워크 세대교체.
  - **사설·칼럼은 싣지 않는다**([사설]·[칼럼]·[기고]·[시론]·[ET톡]).
    **단 이 규칙은 지면 한정이다.** tier0 전체로 넓히지 말 것.
    **[주末머니]·[로보 인사이트]·[비즈360] 같은 매체 연재 태그는 칼럼이 아니다.**
  - 다만 **AI·반도체·로봇·데이터센터가 얽혀 있으면 남긴다.**

**중복 제거 규칙**
- **`[최근 발송분으로 제외]` 목록과 `[중복의심]` 표시를 눈으로 확인한다.**
  기계의 '같은 사건' 판정이 틀릴 수 있다. 다르면 되살려 싣는다.
- **`run.sh hist` 는 프롬프트의 '최근 5회분' 보다 넓게 본다(30일).**
  프롬프트 목록에 없어도 hist 에 어제 발송분이 잡히면 그게 맞다(실측 09-18:
  앤트로픽 호주 DC·엔비디아구글 전력연합을 hist 로 잡아 강등).
- **'같은 주제'는 '같은 사건'이 아니다.** 주체가 다르면 다른 사건이다.
- 어제 나간 사건의 후속 보도라도 **새 사실·새 앵글이 있으면 살린다.**
  다만 **이미 실은 사건에 당사자 코멘트가 붙은 것**, **두 입장이 각각 나간 뒤의
  '충돌' 종합 기사**, **연례 반복 예산 기사**는 새 사실이 아니다.
- **디지털트윈은 사내 R&D 주제라 상시 관심 대상이다.**

### (3) '고' 본문 확인 → 과거 이력 확인 → 순위(rank)
```
bash cowork/run.sh bodygo        # timeout_ms 175000
bash cowork/run.sh bodypeek <idx> <idx> ...   # 리드 700자
bash cowork/run.sh hist          # '고' 전량의 최근 30일 발송 이력 — 생략 금지
bash cowork/run.sh repeat        # 반복 게이트(과거제외·중복발송·재집계)
bash cowork/run.sh grid          # 네 축 비교표(선택)
```
- `bodygo` 는 verdict 의 '고' 전량 본문을 받는다(`body` 는 기계 점수 상위
  300건이라 판정 집합과 어긋난다).
- **전문을 읽지 말고 리드만 본다.** 제목에 안 드러난 알맹이, 인물 기사의
  '1명인가 연쇄인가'.
- **리드가 네비게이션 쓰레기뿐이거나 다른 날짜 기사면 그 링크를 의심한다.**
  (실측 09-18: 미스트랄 시리즈D 링크의 본문이 2024년 시리즈B 기사여서 '중' 강등.)
- `hist` 의 **★(3회 이상 나간 이야기)** 와 **[주체겹침]** 은 이어달리기 기사인지
  본문으로 확인하라는 표시다. 자동으로 빼지 않는다.
- **`hist` 를 반드시 돌린다.** 09-21 에 건너뛰었다가 중복 발송이 났다.
  그리고 **`repeat` 이 종료코드 0 이 될 때까지** 사유를 채운다.

**순위는 판정 사유를 그대로 가중치로 쓴다. 인상으로 다시 매기지 말 것.**

  (가) **판정 사유에 아래가 붙은 건을 최상단으로 올린다.**
       F1(1천억원 이상, 단 기자재·단순물량 제외) · 지정학 · 소버린 ·
       독파모/모두의AI · 국책과제(F5) · 경쟁사+핵심어젠다(F10) ·
       **빅테크·프런티어랩의 신규 모델·제품·요금제 출시(GA 포함)** ·
       **휴머노이드 신제품 공개** ·
       E축 예외 (a)경쟁사 B2B 공략 (b)로봇 새 영역 (c)세그먼트 신규출시+사회이슈
       (d)글로벌 로봇 행사 (e)선도기업 CEO 핵심어젠다
  (나) 그다음 네 축으로 줄 세운다(09-15 확정):
       1 사업적용  최우선3 > 하는사업 > 경쟁사 > 검토중 > 간접 > 없음
       2 확정성    일어남 > 확정계획 > 추진·협상 > 전망·관측
       3 파급      산업구조 > 시장판도 > 개별기업
       4 체급      1~3 이 비슷할 때 갈린다 (⟨체급⟩ 표시)
       **최우선 3개 = 모두의 AI · 독파모 · AI DC.** 여기 걸리면 rank 최상단.
  (다) 1축이 낮아도 파급이 '산업구조' 급이면 올린다. 사유에 `역전:<파급 근거>`.
  (라) (가)의 사유가 없는 '고'를 (가)가 붙은 건보다 위에 두려면 reason 에 이유를 적는다.

**매긴 순위를 verdict.csv 의 rank 열에 1부터 연속으로 적는다.**
'중'·'저' 는 비워 둔다. 그다음 `bash cowork/run.sh verdict` 를 다시 돌려
**종료코드 0** 을 확인한다.

### (4) 발송본 작성 — `out/brief-<날짜>.md`
**쓰기 전에 `bash cowork/run.sh config` 를 연다.** 카테고리·건수·본문 길이·
메시지 상한의 **현재 값**을 코드에서 파싱해 보여준다. 메모리·문서의 숫자를
믿지 말 것 — 값이 다르면 코드가 이긴다.

  1) rank 1위부터 차례로 담는다. **'고'가 적으면 적은 대로 끝낸다.
     '중'으로 자리를 채우지 말 것.** (목표 15~20건, 20건 초과 금지)
  2) 길이는 `run.sh config` 가 알려주는 값을 쓴다
     (2026-09-10 기준: 주요 내용 80자 안팎 / 시사점 50~80자).
     **'(관련 조직: ...)' 태그는 2026-09-09 에 폐지됐다. 붙이지 말 것.**
  3) `bash cowork/run.sh send dry` 로 **메시지 개수**를 확인한다.
     **상한은 원문·HTML 글자수가 아니라 텔레그램 파싱 후 텍스트 길이(4080)** 다.
  4) 메시지가 2개면 **먼저 본문을 압축**하고, 그래도 넘치면
     **rank 최하위 건을 빼고** 3)으로 돌아간다.
  5) **뺀 건의 rank 를 보고에 적는다.**

**카테고리는 `run.sh config` 의 목록·순서를 그대로 쓴다**(2026-09-15 기준 7개 +
국책과제 + 기타). 배치를 정하는 질문 하나 — **"이 기사가 말하는 게 모델인가,
그 모델이 하는 일인가."** 시사점과 카테고리가 다른 말을 하면 둘 중 하나가 틀렸다.

**헤드라인·매체·링크·발행일은 후보 목록 값 그대로 쓴다.**
tier0 항목이 `[제목]` 처럼 대괄호로 감싸여 오는 것만 벗긴다.
같은 사건에 국문·영문이 다 있으면 **국문 우선**. 단 출처가 그 회사 공식
블로그·뉴스룸이면 영문을 그대로 쓰고, **영문 헤드라인을 번역하지 않는다.**
**후보의 링크가 커뮤니티 전재글(fmkorea 등)이면 브리프에 쓰지 말고**
웹검색으로 원 매체·포털 링크를 찾아 바꾼 뒤 보고에 사유를 적는다(실측 09-18).

**국책과제 섹션(3단계에서 챙겨둔 공고 점검 결과)**
**대기업 참여 가능**으로 판정된 공고만 항목으로 만든다.
링크는 공고 원문 URL 그대로. 주요 내용에 공고기관/지원 규모·형태/접수마감일 포함.
'대기업 참여 불가'·'해당 없음'은 싣지 않는다. 0건이면 섹션 자체를 만들지 않는다.

**`brief20-<날짜>.md` 는 만들지 않는다.**

## 8단계 - 검증
순서: `linkcheck` → `cats` → `insight` → `deals` → `verdict` → `push`

### (1) 후보 목록 대조
```
cd <작업본 폴더> && python3 - <<'EOF'
import json,re,datetime
d=datetime.date.today().isoformat()
p=open('out/prompt-%s.txt'%d,encoding='utf-8').read()
allowed={json.loads(m.group(0))['url'] for m in re.finditer(r'^\{"idx".*$',p,re.M)
         if json.loads(m.group(0)).get('url')}
b=open('out/brief-%s.md'%d,encoding='utf-8').read()
urls=re.findall(r'\]\((https?://[^)]+)\)',b)
print("기사 수:",len(urls)," 후보목록 밖 링크:",len([u for u in urls if u not in allowed]),
      " 중복:",len([u for u in set(urls) if urls.count(u)>1]), " 글자수:",len(b))
EOF
```
'후보목록 밖 링크'는 셋만 허용한다: (1) [링크 미확보 후보]에서 웹검색으로 찾은 것
(2) 국책과제 공고 URL (3) 후보 목록의 URL 을 내가 줄여 쓴 것(그 경우 원래 값으로 되돌린다).
그 외가 뜨면 고친다. **(1)~(2)에 해당하면 지우지 말고 보고에 사유를 적는다.**
**카테고리별 기사 번호가 각각 1부터 이어지는지도 확인한다.**

### (2) 브리프 링크 검사 + 제목 정렬 (생략 금지)
```
bash cowork/run.sh linkcheck              # timeout_ms 175000
```
- **'실패'가 있으면 발송하지 않는다.** 그 항목을 고치고 다시 돌린다.
- **`검사 커버리지 N/M` 을 확인한다.** 종료코드 2 면 자동 재시도한다.
- 이 명령은 `retitle` 을 자동으로 이어 돌려 헤드라인을 실제 기사 제목으로 맞춘다.
  - `겹침낮아 보류` 가 있으면 링크가 다른 기사일 수 있다. 눈으로 대조한다.
  - **retitle 이 제목을 자르거나 매체명 꼬리·HTML 엔티티를 되살린다.**
    linkcheck 를 다시 돌리면 **또 되살아난다.** send 직전에
    마지막에 `grep -nE "&#|hellip|middot|: 네이트 뉴스|- 머니투데이"` 로
    확인하고 손으로 지운다.
  - **retitle 로 제목이 길어졌으면 `send dry` 로 길이를 다시 확인한다.**
  - 교체 건수를 보고에 한 줄 적는다.

### (3) 카테고리 검사 (생략 금지)
```
bash cowork/run.sh cats
```
목록 밖 섹션·순서 어긋남·번호 불연속이면 종료코드 1. 기계 분류와 다른 배치는
경고만 — **본문을 근거로 다르게 놓은 것이 맞는지** 다시 묻는 용도다.
기계가 '기타'로 준 건은 손배치 필수 구간이다.
**발송을 안 하는 날에도 반드시 손으로 돌려 종료코드 0 을 확인한다**(send 가
자동 호출해 주던 것이므로, 발송을 생략하면 이 게이트도 같이 사라진다).

### (4) 시사점 점검 / 큰 딜 점검 / 나머지 게이트
```
bash cowork/run.sh insight
bash cowork/run.sh deals
bash cowork/run.sh verdict     # newfact·case·agenda 를 함께 돌린다
```
`deals` 는 1천억원 이상인데 브리프에 없는 딜을 찍는다(경고용).
빠진 건은 **사유를 댈 수 있어야 한다.** 허용 사유는 셋 —
(가) 이미 다른 후보로 브리프에 있다 (나) D축 배제 항목이다
(다) **기자재 납품·단순 물량이다.** 그 셋이 아닌데 뺐다면 **rank 몇 위였는지와
함께** 보고에 적는다.

전부 통과하면 `bash cowork/run.sh push`.

**산출물을 덮어쓰지 말 것.** 검증하겠다고 brief.py 나 refine.py 를 다시 돌리면
그날 프롬프트의 extend 블록이 날아가고 ranked 도 갈린다.

## 9단계 - 판정 엑셀 만들고 멈춘다 (발송하지 않는다)
```
bash cowork/run.sh send dry        # 발송이 아니라 길이·메시지 개수 확인용
bash cowork/run.sh verdict-xlsx    # out/판정-<날짜>.xlsx (요약/전수판정/발송본 3시트)
bash cowork/run.sh push
```

- 산출물은 `out/brief-<날짜>.md` 와 `out/판정-<날짜>.xlsx` **둘**이다.
- `send dry` 의 **메시지 1개**를 확인한다. 2개면 7단계 (4)로 돌아가 본문을 압축하거나
  rank 최하위 건을 뺀 뒤 다시 센다. (상한은 텔레그램 파싱 후 텍스트 4080자)
- **`run.sh send` 는 여기서 돌리지 않는다.** 사용자가 엑셀을 보고 최종 검토한 뒤
  "보내"라고 말하면 그때 돌린다(2026-09-18 지시).
- 검증 게이트(`cats`·`newfact`·`case`·`agenda`)는 send 가 자동 호출하던 것이므로,
  **발송을 안 하는 날에도 8단계에서 손으로 다 돌려 종료코드 0 을 확인한다.**
  게이트를 우회하지 말 것.

### 사용자가 "보내"라고 한 뒤에 할 것
`bash cowork/run.sh send`
- 발송 대상은 **초안 검토용 채널 'DTB 자동화'**(TELEGRAM_DRAFT_CHAT_ID)다.
  **운영 채널로 직접 보내지 않는다.** `run.sh send final` 은 절대 쓰지 말 것.
- push **뒤에** 돌린다. send 는 마운트의 `out/brief-<날짜>.md` 를 읽는다.
- 출력의 `[발송] i/N ok` 가 전부 나오는지 확인한다. 실패하면 그대로 보고한다.
    401 → 토큰 / 403 → 봇 권한 / 400 can't parse entities → 본문 문자 문제
- 이미 보낸 뒤 브리프를 고쳤다면 `run.sh tg-del <message_id>` 로 지우고 다시 보낸다.
- 발송본을 고쳤으면 **`verdict-xlsx` 를 다시 돌려** 발송본 시트를 맞춘 뒤 push 한다.

**사용자가 발송본을 고치면(뺀 것/넣은 것) 같은 턴에 `run.sh review` 를 돌린다.**
제외 이력(`config/rejected.jsonl`)과 사례집(`docs/사례집.md`)에 한 번에 들어간다.
`run.sh case` 는 사례집만 갱신하므로 **더는 단독으로 쓰지 않는다**(09-18 에
제외 이력이 안 남아 09-21 에 같은 기사 3건이 되살아났다).
이유를 말해주지 않았으면 **지어내지 말고 한 줄로 물어본다.**

## 10단계 - 보고 (그리고 발송 대기)
`out/brief-YYYY-MM-DD.md` 와 `out/판정-YYYY-MM-DD.xlsx` **둘 다** 사용자에게 전달한다.
(연결 폴더가 붙어 있으므로 `device_stage_files` → `SendUserFile` 로 채팅에 올린다.)

**보고 첫 줄에 "발송하지 않고 대기 중"이라고 명시한다.** 사용자가 엑셀을 보고
뺄 것/넣을 것을 알려주면 그때 반영해서 9단계의 send 를 돌린다.

그리고 **채팅 답변 본문에 발송본 목록을 직접 적는다.** 파일 링크만 걸지 말 것.
카테고리별로 `번호. 헤드라인 (매체)` 한 줄씩, 링크는 `[원문](URL)` 인라인으로.

이어서 2~3문장으로
(1) tier0 건수와 후보 규모,
(2) **삼성 슬랙 건수·링크 보유율 + SKT NewsClips 슬랙 건수·링크 보유율**,
(3) **링크 검사 결과 — tier0 와 브리프 각각 `OK/의심/실패/미확인` 과
    `검사 커버리지 N/M`.** 커버리지가 미달이었으면(종료코드 2) 반드시 적는다,
(4) **retitle 교체 건수와 '겹침낮아 보류' 건수**,
(5) 8단계 후보목록 대조 결과,
(6) **전수 판정 결과 — 후보 N건 중 고 x / 중 y / 저 z, 그중 발송본에 M건.**
    `send dry` 기준 메시지 개수와 텔레그램 글자 수. 1개가 아니면 그 이유,
(7) **본문 보유율(`본문 보유율 N/M`)과 bodygo 로 확인한 '고' 본문 건수**,
(8) **rank 몇 위에서 잘렸는지**(분량 컷 경계),
(9) 눈에 띄는 헤드라인 1~2개.
국책과제를 실었으면 공고명과 마감일을 한 줄 덧붙인다.

**전일 채점 결과와 "'저' 판정 중 정답지 N건" 은 적지 않는다**(2026-09-17 폐지).

아래는 있었을 때만 적는다:
- 3단계 slack-save 경고, **slack-save 건수와 tier0 파싱 건수 불일치**
- 4·5단계 **채널 미게시·0건 파싱·링크 보유율 90% 미만 경고**
- 6단계 extend 누락 경고, **body 의 `받기 실패` 내역과 보유율 60% 미만 경고**
- 7단계 **사람큐레이션 N건 중 M건 채택**과 뺀 건의 사유
- 7단계 **`agenda` 게이트에 걸려 해명한 건**(기자재·물량·동일주체)
- 7단계 **`hist` 의 ★·[주체겹침] 이 붙었는데 실은 건**과 그 사유
- 7단계 **`hist`·본문 대조로 '고' 에서 강등한 건**과 그 사유
- 7단계 **`[중복의심]` 이 붙었는데 되살린 건**과 그 사유
- 8단계 **`deals` 에서 빠진 큰 딜**과 그 사유, **`cats` 의 손배치 확인 항목**
- 7단계 지면(NewsClips)에서 **AI 무관·사설로 뺀 건수**
- 6단계 **tier2 / links / body / bodygo 반복 횟수**와 **총 소요시간**
  (기대치: tier2 2회 / links 5~10회 / body 2~4회 / bodygo 1회, 전체 40분 안팎)
  **links 의 `못찾음 / 네트워크성` 최종 합계**도 한 줄 적는다.

  잘렸다면 호스트 상한이 바뀐 것이므로 **실측값을 보고에 남긴다.**
