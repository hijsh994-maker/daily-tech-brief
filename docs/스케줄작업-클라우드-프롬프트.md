# 스케줄 작업 프롬프트 — 클라우드 전용 (2026-10-15 작성)

> 아래 `---` 사이를 그대로 스케줄 작업의 프롬프트로 붙여넣는다.
> **"이 컴퓨터 필요(requires local device)" 는 끈다.** 클라우드 세션 혼자 돈다.
> 저장소 주소 두 곳(`<GITHUB_USER>`)만 본인 계정으로 바꾼다.

Brian의 'Daily Tech Brief' 뉴스 파이프라인을 **클라우드 세션에서** 실행한다.
후보 전 건을 판정하고, '고' 중 텔레그램 한 메시지 분량을 골라 발송본을 만들고,
판정 엑셀을 낸 뒤 초안 채널(DTB 업로드)로 텔레그램 발송까지 한다.
사용자 확인을 기다리지 않는다(2026-09-22 지시). `send final` 은 절대 쓰지 않는다.

## 0단계 — 저장소 받기 (이 작업은 연결 폴더가 없다. 저장소가 폴더다)
```
cd ~ && rm -rf dtb dtb-secrets
git clone --depth 1 https://github.com/<GITHUB_USER>/daily-tech-brief.git dtb
git clone --depth 1 https://github.com/<GITHUB_USER>/dtb-secrets.git dtb-secrets
cd ~/dtb && pip install pyyaml truststore holidays openpyxl --break-system-packages -q
bash cowork/run.sh workday        # 종료코드 3 이면 아무것도 하지 않고 끝낸다(휴일). 알림도 보내지 않는다
bash cowork/run.sh sync
```
- clone 이 인증 오류로 실패하면 **즉시 멈추고** PushNotification 으로 "GitHub 인증 실패, 파이프라인 미실행"을 알린다.
  다른 방법으로 코드를 구하려 하지 말 것.
- `~/dtb-secrets/secrets.env` 가 없으면 네이버 링크 해결·텔레그램 발송이 안 된다. 없으면 같은 식으로 알리고 멈춘다.
- `/sessions/*/mnt/` 경로, `device_stage_files`, `device_bash` 는 **이 작업에 없다.** 절차서에 그 말이 나오면
  전부 `~/dtb` 안의 파일을 직접 읽고 쓰는 것으로 읽는다. 작업본 `/tmp/dtb-*` 와 `run.sh push` 는 종전 그대로 돈다.

## 1단계~10단계 — 절차서를 따른다
**절차서는 `~/dtb/docs/실행지침-DTB.md`** 이고, 정본은 `~/dtb/docs/운영지침-변경이력.md` 다.
둘 다 **처음부터 읽고** 그대로 따른다(2단계 persona → 3단계 Slack MCP 로 tier0 수집 → … → 9단계 send → shadow → 10단계 보고).
클라우드에서 달라지는 것은 아래 다섯 가지뿐이다.

1. **마운트 = 저장소.** `MNT` 는 `~/dtb` 다. `run.sh` 가 스크립트 위치에서 알아서 잡는다. 경로를 손으로 적지 말 것.
2. **`run.sh push` 뒤에 반드시 `bash cowork/run.sh cloud-push` 를 돌린다.** 8단계 끝, 9단계 verdict-xlsx 뒤, send 뒤 — 종전에 push 하던 자리마다.
   cloud-push 는 push + `git add/commit/push origin` 이다. **이걸 빠뜨리면 그날 판정·발송본·제외 이력이 전부 사라진다**(세션이 끝나면 컨테이너가 사라진다).
   push 가 실패하면 알림에 적는다. 커밋은 남아 있으니 다음 호출에서 다시 `cloud-push`.
3. **10단계 파일 전달은 `SendUserFile` 로 직접 올린다.** 경로는 `~/dtb/out/brief-<날짜>.md` 와 `~/dtb/out/판정-<날짜>.xlsx`. `device_stage_files` 는 쓰지 않는다.
4. **bash 호출 상한은 종전과 같이 짧게 본다.** tier2/links/body 는 timeout 175000 으로 한 번에 하나씩.
5. **월 1회(매달 첫 영업일)** `bash cowork/run.sh cloud-prune` 을 9단계 뒤에 돌리고 cloud-push 한다. 90일 지난 큰 산출물을 지워 저장소 비대화를 막는다.

## 10단계 보고에 한 줄 추가
`클라우드: clone <커밋 해시> / cloud-push <성공·실패와 해시>`. push 실패는 PushNotification 첫 문단에도 적는다.

나머지(게이트 실패 시 경고만 남기고 발송, 반향 한 줄, 섀도 한 줄, 전수판정 숫자, 발송본 목록을 채팅에 직접 적기 등)는 절차서 10단계 그대로다.
