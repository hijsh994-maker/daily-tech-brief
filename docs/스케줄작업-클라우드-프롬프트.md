**다른 두 저장소 읽기** — 이 세션의 GitHub MCP·`gh`(api.github.com)는 프록시가 daily-tech-brief 로만 허용한다(10-20 실측: 다른 저장소는 PAT 를 넣어도 403). 반면 `git clone https://github.com/…` 은 통과하므로 PAT 로 **얕은 clone** 해서 데이터 파일만 읽는다. 토큰은 환경변수로만 다루고 어디에도 적지 않는다:

## 마무리 보고 (이 세션의 최종 응답) + PushNotification 한 번
PushNotification(`<routine_summary>`) 첫 문장은 ④ 의 발송 결과(`[발송] i/N ok`, message_id, 채널), 둘째 줄은 `run.sh stats --oneline` 한 줄, 그다음 ① 한 줄(신규 공고 N건 게시/없음/이미 게시됨, 신선도 문제), ② 한 줄(삼성 N항목·링크 미확보 K건 / 건너뛴 이유), ③ 한 줄(에이닷 기사 링크 N건 / 미수집이면 그 사실), 각 단계 실제 시작 시각(HH:MM), 게이트 실패가 있으면 이름과 사유,
`클라우드: pull <커밋 해시> / 비밀키 출처 (a|b|c) / GH_FETCH_TOKEN 유무 / cloud-push <성공·실패와 해시>`. push 실패는 첫 문단에도 적는다.
채팅 보고는 절차서 10단계 그대로(발송본 목록을 직접 적기, 전수판정 숫자, 반향 한 줄, 섀도 한 줄 등)에 ①②③ 의 상세(사이트별 공고 수·제외 사유·중복 제외 내역·permalink / 삼성 게시 건수·메시지 링크·대체 링크·미확보 항목 / 에이닷 DATE·COUNT·링크 수)를 앞에 붙인다.
