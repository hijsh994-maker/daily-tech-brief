## 0단계 — 저장소 준비 (이 작업은 연결 폴더가 없다. 미리 체크아웃된 저장소가 폴더다)
이 세션에는 GitHub 저장소 `hijsh994-maker/daily-tech-brief` 가 **이미 클론되어 있다**
(보통 현재 디렉터리. 아니면 `/home/claude/daily-tech-brief`, 그것도 아니면 `git rev-parse --show-toplevel`).
그 폴더를 **REPO** 라 부른다. **`~/dtb` 로 새로 clone 하지 않는다** — 세션 안에서 새로 받은 코드는
실행이 차단된다(2026-10-20 실측). 미리 체크아웃된 폴더의 스크립트만 실행한다.

**비밀키(secrets.env) 확보** — 아래 순서로 처음 되는 것을 쓴다. 최종 위치는 `$REPO/cowork/secrets.env`
(.gitignore 가 걸러 커밋되지 않는다). 키 값은 채팅·보고·알림·커밋 어디에도 적지 않는다.
- (a) `$REPO/cowork/secrets.env` 가 이미 있으면 그대로 쓴다.
- (b) `git clone --depth 1 https://github.com/hijsh994-maker/dtb-secrets.git "$REPO/../dtb-secrets"` 가 되면
  run.sh 가 `../dtb-secrets/secrets.env` 를 자동으로 찾는다. 인증 오류면 **재시도하지 말고** (c) 로 간다.
- (c) Google Drive 커넥터: `mcp__Google_Drive__search_files` 로 `title = 'dtb-secrets'` 인 Google 문서를 찾아
  `mcp__Google_Drive__read_file_content` 로 읽고, `KEY=VALUE` 꼴의 줄만 골라(앞뒤 공백·따옴표 제거)
  `$REPO/cowork/secrets.env` 에 Write 한다. 필요한 키: NAVER_CLIENT_ID, NAVER_CLIENT_SECRET,
  TELEGRAM_BOT_TOKEN, TELEGRAM_DRAFT_CHAT_ID (있으면 TELEGRAM_FINAL_CHAT_ID, TELEGRAM_FANOUT_* 도 그대로).
- 셋 다 안 되면 **즉시 멈추고** PushNotification 으로 "비밀키 없음, 파이프라인 미실행" 을 알린다.

  "run.sh 실행 차단, 파이프라인 미실행" 을 알린다. 차단 사유 문구를 그대로 적는다.

## 1단계~10단계 — 절차서를 따른다
**절차서는 `$REPO/docs/실행지침-DTB.md`** 이고, 정본은 `$REPO/docs/운영지침-변경이력.md` 다.
둘 다 **처음부터 읽고** 그대로 따른다(2단계 persona → 3단계 Slack MCP 로 tier0 수집 → … → 9단계 send → shadow → 10단계 보고).
클라우드에서 달라지는 것은 아래 다섯 가지뿐이다.

1. **마운트 = 저장소.** `MNT` 는 `$REPO` 다. `run.sh` 가 스크립트 위치에서 알아서 잡는다. 경로를 손으로 적지 말 것.
2. **`run.sh push` 뒤에 반드시 `bash cowork/run.sh cloud-push` 를 돌린다.** 8단계 끝, 9단계 verdict-xlsx 뒤, send 뒤 — 종전에 push 하던 자리마다.
   cloud-push 는 push + `git add/commit/push origin` 이다. **이걸 빠뜨리면 그날 판정·발송본·제외 이력이 전부 사라진다**(세션이 끝나면 컨테이너가 사라진다).
   push 가 실패하면 알림에 적는다. 커밋은 남아 있으니 다음 호출에서 다시 `cloud-push`.
3. **10단계 파일 전달은 `SendUserFile` 로 직접 올린다.** 경로는 `$REPO/out/brief-<날짜>.md` 와 `$REPO/out/판정-<날짜>.xlsx`. `device_stage_files` 는 쓰지 않는다.
4. **bash 호출 상한은 종전과 같이 짧게 본다.** tier2/links/body 는 timeout 175000 으로 한 번에 하나씩.
5. **월 1회(매달 첫 영업일)** `bash cowork/run.sh cloud-prune` 을 9단계 뒤에 돌리고 cloud-push 한다. 90일 지난 큰 산출물을 지워 저장소 비대화를 막는다.
