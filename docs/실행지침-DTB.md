### SKT NewsClips (지면 스크랩) — **슬랙 이메일 게시** [2026-09-17 전환]
**지메일을 쓰지 않는다.** 옮길 계정에 Gmail 커넥터가 붙지 않아 채널 이메일
주소로 받는다. 슬랙은 이 메일을 **메시지가 아니라 `text/html` 파일 첨부**로
만든다. 그래서 `slack-save` 경로로는 **0건**이 나온다.

(1) 3단계에서 읽은 #dtb-tier0 응답에서 오늘 날짜 항목을 찾는다:
```
=== Message from Slackbot (USLACKBOT) at YYYY-MM-DD HH:MM KST ===
Files: [YYYY년 M월 D일] 조간 뉴스 클리핑 (ID: F..., text/html, NN KB)
```
    **메시지 텍스트가 비어 있는 것이 정상이다.** '메일이 안 왔다'고 오판하지 말 것.
    같은 채널에 `FW: News Clips(M월 D일)` 같은 11MB 첨부가 함께 올라올 수 있는데
    그건 다른 파일이다. **「조간 뉴스 클리핑」 제목의 것을 집는다.**
(2) `slack_read_file(<그 file ID>)` 로 파일을 읽는다.
    응답이 커서 도구가 파일로 떨어뜨리면 그 파일을 그대로 표준입력으로 넣는다
    (내용을 다시 타이핑하지 말 것).
(3) 응답을 **그대로** 히어독으로 넘긴다(헤더·`<file_content>` 래퍼 포함, 가공 금지):

```
bash cowork/run.sh newsclips-slack <<'RAW'
<slack_read_file 응답 전체>
RAW
```

- **주제 필터는 두지 않는다. 파싱된 것을 전량 주입한다.**
  조간 지면 **전체**라 AI 무관 기사가 섞여 있다. 7단계 판정에서 거른다.
- 출력의 **`링크 보유 N/M`** 이 90% 미만이면 경고가 뜬다. 보고에 적는다.
- **`[경고] '링크:' 뒤가 모두 비었습니다`** 가 뜨면 `body-plain-without-links`

- 채널에 아직 안 올라왔으면 조용히 건너뛰되 **보고에 반드시 한 줄 적는다.**
- 미리보기만: `newsclips-slack dry` (원문 저장 안 함)
- 지메일이 살아 있는 계정에서 과거 날짜를 되짚을 때만 `newsclips-mail` 을 쓴다.

**tier0 소스는 4개다: slack(#3_트렌드) / adot / samsung(슬랙) / newsclips(슬랙).**
(여기에 6단계의 community 가 tier0 급으로 더해진다. 09-23 신설.)

### 5-1단계 - tier0 링크 검사 (생략 금지)
```

```
- URL 모양(목록/홈 페이지) + HTTP 404/410 + 제목 대조 세 가지를 본다.

- **'실패' 판정 URL 은 자동으로 비운다.** 뒤의 `run.sh links` 가 다시 찾는다.
- **'의심'은 자동으로 손대지 않는다.** 페이지 제목이 함께 찍히니 눈으로 보고,

  (지면 제목과 온라인 제목이 달라서 뜨는 '의심'이 대부분이다. 같은 기사면 둔다.)
- 반드시 **refine 앞에** 돌린다.
- **'미확인' 숫자만 보지 말고 `검사 커버리지` 줄을 볼 것.**
  종료코드: **0 정상 / 1 고쳐야 할 링크 있음 / 2 검사 커버리지 미달**
  2 가 나오면 run.sh 가 자동으로 1회 재시도한다. 그래도 2 면 보고에 적는다.
- 보고에 `OK/의심/실패/미확인` 과 **`검사 커버리지 N/M`** 을 적는다.

## 6단계 - 파이프라인
`bash cowork/run.sh tier2` → `tier2-done` → **`community`** → **`buzz`** → `refine` → `links`(반복) → **`body`(반복)** → `brief` → `extend`

**[2026-09-23] `community` 와 `buzz` 는 tier2-done 뒤·refine 앞에 반드시 돌린다.**
둘 다 timeout_ms 45000 이면 된다. 출력의 `[community] HN N / GitHub N / HF N` 과
`[buzz] … 반향 후보 N건` 상위 3개 낱말을 보고에 적는다. 빠뜨리면 refine 이 조용히
예전처럼 돌고(경고 없음) 반향후보 그룹이 비어 나온다.

**tier2 / links / body 는 전부 timeout_ms 175000 으로 부른다. 인자를 붙이지 말 것.**

- tier2 는 재개형이다. '남음 N개' 가 없어질 때까지 반복한 뒤
  `bash cowork/run.sh tier2-done` 으로 마감해야 out/tier2-<날짜>.json 이 생긴다.
- **[2026-10-20] 클라우드(마운트=git 저장소)에서는 `run.sh refine` 이 자동으로 `--no-links` 로 돈다.**
  실측 10-20: 클라우드 프록시에서 네이버 API 연결이 끊겨 refine 이 175초에서 죽었다(3분 손실).
  그러니 클라우드에서는 refine 뒤에 **바로 `run.sh links` 를 '전부 시도 완료'까지 반복**한다.
  (PC는 종전과 같다. 강제: `DTB_REFINE_LINKS=1` / `DTB_REFINE_NO_LINKS=1`)
- refine 이 죽으면 링크 해결이 원인이다. 이렇게 나눈다:
    `cd $W && python3 refine.py --date <날짜> --min-score 6 --max-items 300 \
       --max-rescue 150 --no-links`   (1~2초)
    그다음 **`bash cowork/run.sh links`** 를 '남았습니다'가 안 나올 때까지 반복.

**links 는 실패 사유를 갈라 찍는다.**
  `확보 N / 못찾음 N / 네트워크성 N / 건너뜀 N / 남음 N(재시도 대기 N)`
  - **못찾음** = 네이버에 그 기사가 정말 없다. 재시도하지 않는다.
  - **네트워크성** = 회복 가능하므로 미시도분을 다 소진한 뒤 한 번 더 시도한다.
  '전부 시도 완료' 가 나올 때까지 반복한다.
  - **워커를 8보다 올리지 말 것.** 병목은 네이버 쿼터이고 처리량은 초당 0.4건 고정이다.

**`bash cowork/run.sh body` — 본문 재채점. 생략 금지.**
- links 를 다 채운 뒤, brief **앞에** 돌린다. 순서가 바뀌면 소용없다.
- 재개형이다. '남았습니다'가 안 나올 때까지 반복(**2~4회**).
- **아래 두 줄을 확인하고 보고에 적는다.**
    `받기 실패 N건 -> 타임아웃 N / HTTP 403 N / 본문짧음 N`
    `본문 보유율 N/M (P%)`  ← **60% 미만이면 경고가 뜬다. 뜨면 반드시 보고한다.**

**brief 뒤 extend 가 실제로 붙었는지 즉시 확인한다.**
`grep -c "^\[링크 미확보 후보\]" out/prompt-<날짜>.txt` 가 **1** 이어야 한다.
0 이면 미확보 150건이 통째로 빠진 것이고, 그 프롬프트로 한 선별은 무효다.
(`extend` 가 '이미 덧붙여져 있음. 건너뜀' 을 찍어도 grep 이 1 이면 정상이다.)

## 7단계 - 전수 판정 → 순위 → 발송본 작성

### (1) 점수를 가린 목록 + 타임라인 만들기
```
bash cowork/run.sh carryover inject   # [2026-10-27] 전일 '고' 미발송 이월(C1..)
bash cowork/run.sh late        # [2026-10-27] 경쟁사 속보 재점검(오전 수집 이후 기사)
bash cowork/run.sh blind
bash cowork/run.sh timeline
```
`out/candidates-blind-<날짜>.txt` 는 score·signals 를 빼고 통로별로 묶은 목록이다.
**점수 내림차순이 아니므로 위에서부터 읽어도 '상위/하위'가 없다.**
표시 넷을 함께 읽는다 — `⟨체급⟩`(주체가 이 바닥에서 누구인가) ·
`[중복의심]` · **`[기자재어휘]`**(D축 배제7 후보) · **`[반향: …]`**(09-23 신설). 넷 다 점수가
아니라 **사실**이다. 맨 위 `=== 반향후보 ===`·`=== 커뮤니티 ===` 그룹부터 본다.

`out/timeline-<날짜>.md` 는 최근 30일을 사건 단위로 늘어놓고 오늘 후보를 붙인다.
줄 앞의 `·` 는 **후보로만 올랐고 발송되지 않은** 기사다. **[2026-09-30 정정] `·` 는 독자가
본 것이 아니다** — 여러 날 이어져 있어도 독자 기준으로는 첫 게재이므로 신규성으로 깎지 않는다.

**[2026-09-22 신설] `timeline` 은 끝나면서 그 결론을 blind 목록에 되돌려 찍는다.**
오늘 후보가 붙은 이야기의 과거가 **2건 이상 · 서로 다른 2일 이상 · 전부 `·`(미발송)**
이면 blind 목록 그 줄 끝에 이렇게 붙는다.

```
187 | tier0+교차 | 파이낸셜뉴스 | 09-22 | 소수 | ⟨대기업⟩ [현대차 美공장에
아틸라스 '훈련장'...휴머노이드 2만5000대 배치 준비]  [반복후보 3건·미발송 08-26~09-01]
```

뜻은 **"그 이야기가 과거 여러 날 후보로 올라왔지만 한 번도 실리지 않았다"** 이다.
**[2026-09-30 정정] 표시는 `[후보만 N회·발송 0건 …]` 으로 바뀌었고 감점 근거가 아니다.**
안 실은 것은 대부분 **내가** 안 올린 것이지 편집자가 판단한 것이 아니다. 사용자가 실제로
뺀 이야기는 `config/rejected.jsonl` 에 있고 `run.sh repeat` 가 따로 잡는다. 그 밖의
발송 0건 이야기는 독자에게 첫 게재이므로 알맹이(E축)·단계(C축)로만 판정한다.
(09-29 LLM 재킹 사용자: *"최근에 LLM 재킹 관련 기사를 올린 적이 없으면 넣어야 한다"*)
(09-22 사용자: *"여러 번 기사화된 내용이고, 기사를 보면 중요한 새로운 내용이 없다."*)

표시가 없다고 안심하지 말 것. timeline 이 과거와 못 이으면 `[새]` 로 분류되어
표시가 붙지 않는다. 09-22 의 '소뱅-현대차 RAI연구소'가 그 경우였다 — 그쪽은
**사례집**이 맡는다.

### (2) 전수 판정
**blind 목록 맨 위 `=== 반향후보 ===` 부터 본다(2026-09-23).** [반향: …] 이 붙은 건은
E축 예외 (f)로 판정한다 — 무명 주체여도 제3자 반응(클론·HN·GitHub·경쟁사 대응·
여러 매체의 돌풍·열광)이 실체면 고, 자기 주장뿐이면 저. '고' 사유에 `반향:` 을 남긴다.
`=== 커뮤니티 ===` 그룹(HN·GitHub·HF)은 영문·개발자 관점이라 국내 매체보다 며칠
빠르다. 링크는 원문(HN 링크·레포·모델 페이지) 그대로 쓴다.

**`out/prompt-<날짜>.txt` 의 `[편집자 평가 기준]` 절을 반드시 연다.**
**[2026-09-22] 이 절에 `I. 편집자 수정 사례집` 이 생겼다.** 사용자가 발송본을

### (3) '고' 본문 확인 → 과거 이력 확인 → 순위(rank)
```
bash cowork/run.sh bodygo        # timeout_ms 175000
                                 # → '고' 전량의 리드를 자동으로 찍는다(09-22~)
bash cowork/run.sh bodypeek <idx> <idx> ...   # 리드 700자(개별)
bash cowork/run.sh bodypeek --go              # '고' 전량 다시 찍기
bash cowork/run.sh bodypeek --check           # '고' 전량을 봤는지 검사
bash cowork/run.sh hist          # '고' 전량의 최근 30일 발송 이력 — 생략 금지
                                 # [2026-09-22] 결과를 out/signals-<날짜>.json 에
                                 #   남긴다. 이걸 건너뛰면 판정 엑셀의 '발송이력'
                                 #   열이 비고 verdict-xlsx 가 경고를 찍는다.
bash cowork/run.sh repeat        # 반복 게이트(과거제외·중복발송·재집계)
bash cowork/run.sh grid          # 네 축 비교표(선택)
```
- `bodygo` 는 verdict 의 '고' 전량 본문을 받는다(`body` 는 기계 점수 상위
  300건이라 판정 집합과 어긋난다).
- **[2026-09-22 신설] '고' 전량의 리드 확인은 의무다.** `bodygo` 가 본문을 받은 뒤
  '고' 전량의 리드를 자동으로 찍고, 찍은 idx 를 `out/peeked-<날짜>.json` 에 남긴다.
  **`run.sh rank` 는 그 기록을 검사해 안 본 건이 있으면 멈춘다.** 출력이 지나갔다고
  넘기지 말고 **실제로 읽는다.** 09-22 에 '고' 13건 중 리드를 연 것은 0건이었고,
  그래서 본문 대부분이 AI DC 가 아닌 '정책금융 194.5조' 건이 rank 3 으로 나갔다.
  읽을 때 묻는 것은 두 가지다.
    1. **본문이 헤드라인과 같은 이야기를 하는가.** 말미 한 문단만 우리 주제면 '고'가 아니다.
    2. **같은 사건을 더 정면으로 다룬 기사가 후보 풀에 있는가.** 09-22 정책금융 건은
       전문이 AI DC 인 기사(아이뉴스24)가 같은 풀에 있었고, 그 본문에는
       "별도 재원이나 금리·한도 우대가 새로 생기는 것은 아니다"라고 적혀 있었다.
  **본문 캐시가 없는 '고' 는 이 검사가 막지 못한다.** 검사 출력이 그 idx 를 따로
  찍으므로 링크를 찾아 넣거나, 못 찾으면 등급을 다시 본다.
- **전문을 읽지 말고 리드만 본다.** 제목에 안 드러난 알맹이, 인물 기사의
  '1명인가 연쇄인가'.
- **리드가 네비게이션 쓰레기뿐이거나 다른 날짜 기사면 그 링크를 의심한다.**
  (실측 09-18: 미스트랄 시리즈D 링크의 본문이 2024년 시리즈B 기사여서 '중' 강등.)
- `hist` 의 **★(3회 이상 나간 이야기)** 와 **[주체겹침]** 은 이어달리기 기사인지
  본문으로 확인하라는 표시다. 자동으로 빼지 않는다.
- **`hist` 를 반드시 돌린다.** 09-21 에 건너뛰었다가 중복 발송이 났다.
  그리고 **`repeat` 이 종료코드 0 이 될 때까지** 사유를 채운다.

417건(75%)에 같은 문장 두 개를 붙였다. 사용자 원문: *"또 고로 판정한거 몇개만
하는거 아니지? 불안하다"* → **숫자를 눈앞에 놓는 것이 유일한 확인 경로다.**

`--oneline` 출력을 **PushNotification `<routine_summary>` 의 첫 문장 다음 줄**과
**채팅 보고 첫 문단**에 그대로 붙인다. 형태:

```
판정 557건(고 13·중 192·저 352) / 사유 중 192종·저 349종 / 고 본문확인 10/10 / 게이트 전부 통과
```

읽는 법 — **사유 종류 수가 건수에 가까워야 전수 판정이다.** '중 192종/192건'은
192건을 개별로 판정했다는 뜻이고, '중 8종/417건'이면 대량 라벨링이다.
`고 본문확인 n/m` 이 `m` 에 못 미치면 제목만 보고 '고'를 준 건이 있다는 뜻이다.
게이트가 하나라도 실패했으면 **이름과 사유를 알림 본문에 반드시 적는다.**

---

`out/brief-YYYY-MM-DD.md` 와 `out/판정-YYYY-MM-DD.xlsx` **둘 다** 사용자에게 전달한다.
(연결 폴더가 붙어 있으므로 `device_stage_files` → `SendUserFile` 로 채팅에 올린다.)

**보고 첫 줄에 발송 결과를 적는다** — `[발송] i/N ok`, `message_id`, 채널(초안).
**둘째 줄에 `run.sh stats --oneline` 한 줄을 그대로 붙인다**(판정 건수·사유 종류·본문확인·게이트).
**게이트가 하나라도 실패했으면 그 이름과 사유를 첫 문단에 적는다**(2026-09-22).
푸시 알림(PushNotification)에도 같은 내용을 넣는다. 사용자가 실시간으로 보지 않으므로
알림이 유일한 전달 경로다.

그리고 **채팅 답변 본문에 발송본 목록을 직접 적는다.** 파일 링크만 걸지 말 것.
카테고리별로 `번호. 헤드라인 (매체)` 한 줄씩, 링크는 `[원문](URL)` 인라인으로.

이어서 2~3문장으로
(1) tier0 건수와 후보 규모,
(2) **삼성 슬랙 건수·링크 보유율 + SKT NewsClips 슬랙 건수·링크 보유율**,
(3) **링크 검사 결과 — tier0 와 브리프 각각 `OK/의심/실패/미확인` 과
    `검사 커버리지 N/M`.** 커버리지가 미달이었으면(종료코드 2) 반드시 적는다,
(4) **retitle 교체 건수와 '겹침낮아 보류' 건수**,
(5) 8단계 후보목록 대조 결과,
(6) **전수 판정 결과 — 후보 N건 중 고 x / 중 y / 저 z, 그중 발송본에 M건.**
    `send dry` 기준 메시지 개수와 텔레그램 글자 수. 1개가 아니면 그 이유,
(7) **본문 보유율(`본문 보유율 N/M`)과 bodygo 로 확인한 '고' 본문 건수**,
(8) **rank 몇 위에서 잘렸는지**(분량 컷 경계),
(9) 눈에 띄는 헤드라인 1~2개.
국책과제를 실었으면 공고명과 마감일을 한 줄 덧붙인다.

**전일 채점 결과와 "'저' 판정 중 정답지 N건" 은 적지 않는다**(2026-09-17 폐지).
