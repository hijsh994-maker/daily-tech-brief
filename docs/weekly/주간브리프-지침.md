# Weekly Tech Brief 작성 지침 (2026-11-11 사용자 확정)

매주 금요일 Daily Tech Brief 텔레그램 발송이 끝난 뒤, 그 주(월~금) 발송본을 묶어 경영진용 주간 자료를 HTML 로 만든다.
**텔레그램·슬랙에는 올리지 않는다.** 결과는 Artifact 페이지 + 저장소 `out/weekly/Weekly Tech Brief M월 N주차.html`.

## 1. 재료
- 그 주 월~금의 `out/brief-<날짜>.md` (휴일은 없다). 발송본에 실린 기사만 쓴다. 새로 검색하지 않는다.
- 숫자·사실은 발송본의 헤드라인·주요 내용에 적힌 것만. 쓰기 전에 문장마다 발송본에서 다시 찾아 대조한다.
  발송본끼리 수치가 엇갈리면 그 숫자는 빼거나 엇갈린다고 적는다.
- 기사 수(N건)는 실제로 센다.

## 2. 구성 (순서 고정 — `docs/weekly/template.html` 과 같다)
1. 머리: `WEEKLY TECH BRIEF` · `YYYY년 M월 N주차 · M/D(월)~M/D(금)` · `일간 브리프 N건 기반` / 제목(그 주를 관통하는 한 줄) / 부제 한 줄
2. 경영진이 가져갈 세 가지: 카드 3장(헤드라인 + 한 줄)
3. 한 주의 흐름: 4줄 안팎. 흐름명 / 일어난 일 / 뜻하는 바
   - 한 가지 지표를 4개 이상 비교할 숫자가 있을 때만 막대 그림을 넣는다(막대 길이는 값에 비례). 없으면 `.raise` 블록을 통째로 뺀다.
4. 인사이트: 3개. 카테고리 태그 / 제목 / 본문 한 문단 / 근거 한 줄
   - 사슬·단계 구조가 실제로 있을 때만 `.chain` 그림을 쓴다(약한 고리 하나만 `weak`). 없으면 뺀다.
5. 제언: 카드 4장 안팎. 시점 라벨 + 카테고리 태그 / 제목 / 정할 것 / 지켜볼 신호
   - **카테고리 태그(2026-11-12 사용자 지시, 계속 유지):** 인사이트·제언마다 DTB 발송본 섹션 이름으로 단다.
     쓰는 이름은 DTB 7개뿐 — AI Model / AI Agent / Enterprise AI / AI DC & Infra / Physical AI / AI 보안&정책 / AI 투자&시장.
     내용의 중심 하나를 먼저, 둘째 축이 분명하면 하나 더(최대 2개). 근거 기사들이 실린 발송본 섹션을 보고 정한다.
     마크업: `<ul class="cats" aria-label="카테고리"><li class="cat">AI DC &amp; Infra</li></ul>` — 인사이트는 h3 위, 제언은 `.top` 안 시점 라벨 옆.
6. 다음 주에 볼 것: 3줄
7. 꼬리: 근거·한계 한 줄 + 근거 기사 링크(흐름별, 발송본의 URL 그대로)

## 3. 내용 수준 (사용자 요구: "단순 시사점이 아니라 경영진이 참고할 통찰과 제언")
- 기사 요약을 나열하지 않는다. 여러 기사를 이어야만 보이는 **구조 변화**를 쓴다(누가 위험을 지나, 병목이 어디로 옮겨갔나, 경쟁의 축이 무엇으로 바뀌었나).
- 인사이트마다 서로 다른 기사 3건 이상이 근거여야 한다. 근거가 약하면 인사이트 수를 줄인다.
- 제언은 '무엇을 정할지'와 '어떤 신호를 볼지'까지. 사내 투자 계획·계약·재무는 모르므로 금액·일정 같은 실행 수치를 지어내지 않는다.
- 독자는 통신·AIDC·B2B AX 사업을 하는 회사의 경영진. 경쟁사(KT·네이버·카카오·LGU+)·최우선 어젠다(모두의 AI·독파모·AI DC) 관점을 우선한다.
- 전주 주간 자료(`out/weekly/`)가 있으면 읽고, 같은 인사이트·제언을 되풀이하지 않는다. 이어지는 흐름이면 무엇이 달라졌는지를 쓴다.

## 4. 문체 — DTB 발송본과 같다
- 명사형 종결, 마침표 없음, 쉼표로 이어 붙임. ("오라클·메타·알파벳, 한 주에 잇달아 채권 발행, 아마존은 장비 담보 대출 약정 체결")
- 제목·카드 헤드라인도 명사형. 핵심 위주로 짧게. 전체 분량은 template 수준을 넘기지 않는다.

## 5. 디자인
- `docs/weekly/template.html` 의 `<style>` 과 구조를 그대로 쓰고 글만 바꾼다. 색·글꼴·배치를 새로 만들지 않는다.
- `<title>` 은 `Weekly Tech Brief M월 N주차`. 주차 = 그 주 월요일이 그 달의 몇 번째 월요일인가.

## 6. 내보내기
1. `out/weekly/Weekly Tech Brief M월 N주차.html` 로 저장 → 화면을 한 번 띄워 가로 넘침·깨짐만 확인.
   - **파일명 규칙(2026-11-12 사용자 지시, 계속 유지):** `Weekly Tech Brief 11월 2주차.html` 처럼 `<title>` 과 같은 이름. 주차 = 그 주 월요일이 그 달의 몇 번째 월요일인가. 예약 작업 지시문에 `weekly-<날짜>.html` 이 남아 있어도 이 규칙이 우선한다.
2. Artifact 도구로 게시(icon `report`, 매주 새 페이지). 
3. `bash cowork/run.sh cloud-push "weekly <날짜>"`.
4. PushNotification: 첫 문장에 제목(그 주의 한 줄), 이어서 세 가지 판단, 기사 수, 게시·push 결과.
