## 먼저 알아둘 말 세 개

- **저장소(repository)**: GitHub 에 만드는 '온라인 폴더'. 파일과 그 변경 이력이 함께 보관된다. 줄여서 '레포'.
- **비공개(Private)**: 그 저장소를 본인만 볼 수 있게 하는 설정. 우리 저장소 둘은 **반드시 Private** 이다.
- **GitHub Desktop**: PC 폴더를 GitHub 저장소로 올려 주는 무료 프로그램. 명령어를 칠 필요가 없다.

## 부록 A. PC 폴더는 어떻게 되나

- 지우지 않는다. STEP 2 를 GitHub Desktop 으로 했다면 PC 폴더가 저장소의 복제본이라, GitHub Desktop 에서 **Fetch origin → Pull** 을 누르면 그날 발송본·엑셀이 PC 폴더에도 내려온다.
- 이관 뒤 사용자 제외(`run.sh review`)·지침 수정은 **저장소 쪽**에 해야 다음 실행에 반영된다. Claude 에게 고쳐 달라고 할 때 "저장소에 반영해서 push 까지" 라고 말하면 된다.
- 윈도우 예약작업(`run_daily.ps1`, collect 45분 주기)은 클라우드 실행과 무관하다. 꺼도 되고 둬도 된다.
- 폴더에 남은 임시 파일 세 개는 지워도 된다: `ziNGioSs`, `zieH8Xwz`(zip 이 남긴 임시 파일, 합쳐 150MB), 0바이트 `_클라우드-꾸러미.zip`.
  꾸러미 본체 `_클라우드-꾸러미-1015.zip` 도 STEP 2 가 끝나면 지워도 된다. (`.gitignore` 가 걸러서 저장소에는 안 올라간다.)

## 부록 B. 저장소 크기

첫 커밋 패킹 약 60MB. 하루 산출물 5~10MB 가 더해진다(git 압축 뒤 2~3MB 안팎).
`run.sh cloud-prune` 을 월 1회 돌리면 90일 지난 큰 산출물이 지워져 연 300MB 안쪽에 머문다. GitHub 권장 상한 1GB 와 충분히 떨어져 있다.
`index/cowork-articles.sqlite`(18MB)는 매일 바뀌어 커밋마다 새 버전이 남는다. 1년 뒤에도 수백 MB 수준이고, 커지면 `git gc` 로 줄인다.

## 부록 C. 왜 비밀키를 따로 두나

코드 저장소는 나중에 공유·복제·백업될 수 있고, 토큰이 한 번 섞이면 이력에서 지우기 어렵다.
`dtb-secrets` 는 파일 하나짜리 저장소라 유출 범위가 명확하고, 토큰을 바꿀 때 그 파일만 고치면 된다.
토큰이 유출됐다고 의심되면 @BotFather 에서 `/revoke` 로 재발급하고 `dtb-secrets` 만 고친다.
